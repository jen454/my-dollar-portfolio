# 운영/마케팅 측면 회고

> 채널 전략, 사용자 행동, 규제 대응, 포지셔닝 관점에서 이 서비스를 되돌아본다.

---

## 틈새시장 (Niche Market) & 가치 제안 (Value Proposition)

넓은 시장 대신 특정 니즈를 가진 좁은 세그먼트를 집중 공략하는 전략. 가치 제안은 사용자가 왜 이 서비스를 써야 하는지의 핵심 이유.

**이 서비스에서:** 타깃은 토스증권에서 달러 예수금을 운용하는 개인 투자자. "내 달러를 평균 얼마에 환전했는지 바로 알고 싶다"는 좁고 명확한 페인 포인트를 공략한다. 증권사 앱에 이 기능이 없거나 불편해서 스프레드시트로 직접 관리하던 사람들이 1차 타깃이다.

---

## 유통 채널 (Distribution Channel)

제품이 사용자에게 도달하는 경로. 앱 자체의 품질만큼 어디서 발견되는지가 중요하다.

**이 서비스에서:** 토스 미니앱 플랫폼 자체가 유통 채널이다. 별도 설치 없이 토스 앱 내 검색에서 발견된다. 토스의 3천만 MAU가 잠재 도달 범위지만, 실제로는 "달러 환전" 관련 검색을 하는 사용자만 접근한다. 토스 정책상 외부 링크를 삽입할 수 없어 앱 밖에서의 바이럴은 제한적이다.

---

## 리텐션 (Retention)

사용자가 첫 방문 후 얼마나 다시 돌아오는지. 서비스 지속 가치의 핵심 지표.

**이 서비스에서:** 리텐션 동인은 두 가지다.

1. **데이터 축적 (Lock-in):** 거래 기록이 쌓일수록 앱을 떠나기 어려워진다. 기록이 많을수록 평균단가 계산의 정확도가 높아지므로 사용자가 계속 기록을 추가할 유인이 생긴다.
2. **반복 확인 행동:** 환율이 변동할 때마다 현재 손익을 확인하고 싶은 욕구가 생긴다. 환율 변동성이 높은 시기에 자연스럽게 DAU가 상승하는 구조다.

리텐션을 위협하는 요소: 앱 재설치 시 localStorage 초기화로 인한 데이터 소실.

---

## 온보딩 (Onboarding)

신규 사용자가 서비스의 가치를 처음으로 경험하게 유도하는 과정. 첫 경험이 리텐션을 결정짓는다.

**이 서비스에서:** 거래 기록이 없을 때 홈에 "아직 거래 기록이 없어요 / 첫 환전 기록을 추가해보세요" 빈 상태(Empty State)를 노출한다.

개선 여지: 처음 앱 진입 시 서비스 가치를 설명하는 스플래시나 툴팁이 없어서 사용법을 직관적으로 파악해야 한다. 첫 거래 기록 추가까지 유도하는 플로우가 약하다.

---

## 면책 고지 (Disclaimer) & 규제 대응

법적 책임 범위를 명시하는 문구. 금융 서비스는 투자 조언과 단순 계산기를 명확히 구분해야 한다.

**이 서비스에서:** 모든 화면 하단에 고정된 문구를 노출한다.

> "한국수출입은행 기준환율 기반 단순 계산기입니다. 투자 조언을 제공하지 않습니다."

금융위원회의 유사투자자문업 규제를 피하기 위한 핵심 장치다. 기능 설계 자체도 이 원칙을 따른다.

- 목표 환율 추천 없음
- 매수/매도 시점 조언 없음
- 수익 예측 없음
- 외부 금융 상품 연결 없음

---

## 서비스 범위 (Scope) — 계산기로의 포지셔닝

서비스가 하는 것과 하지 않는 것의 경계. 명확한 범위는 법적 리스크를 낮추고 사용자 기대를 관리한다.

**이 서비스에서:** 의도적으로 좁은 범위를 유지한다.

| 하는 것 | 하지 않는 것 |
|--------|------------|
| 평균 환전단가 계산 | 환율 예측 |
| 투입 원화 대비 손익 계산 | 매수/매도 타이밍 조언 |
| 거래 기록 관리 | 타 금융 상품 비교 |
| 실시간 환율 조회 | 외부 링크 연결 |

계산기로의 포지셔닝은 규제 리스크를 최소화하는 동시에, 복잡한 기능 없이 핵심 가치에 집중할 수 있는 전략적 선택이다.

---

## 플랫폼 의존성 (Platform Dependency)

특정 플랫폼의 정책·API·사용자에 의존하는 정도. 플랫폼이 규칙을 바꾸면 서비스가 영향을 받는다.

**이 서비스에서:** 토스 앱에 100% 의존한다.

리스크:
- 토스 미니앱 정책 변경 → SDK 강제 업그레이드 필요
- `@apps-in-toss/web-framework` API 변경 → Storage, 네비게이션 코드 수정 필요
- 토스 앱 독립적인 SEO나 외부 마케팅 불가

반면 3천만 규모의 기존 사용자에게 별도 마케팅 없이 접근할 수 있는 것이 최대 장점이다.

---

## 데이터 이식성 (Data Portability)

사용자가 자신의 데이터를 내보내거나 다른 서비스로 가져갈 수 있는 능력.

**이 서비스에서:** 현재 없다. 거래 기록 내보내기(CSV, JSON) 기능이 없어 서비스를 떠나거나 기기를 바꿀 때 데이터를 옮길 방법이 없다.

이는 양면성을 가진다.
- **Lock-in으로서의 리텐션 효과:** 데이터를 떠나기 어렵게 만든다.
- **신뢰 장벽:** "백업할 수 없는 앱은 못 믿겠다"는 이유로 진입을 꺼리는 사용자가 생긴다.

---

## 애널리틱스 이벤트 (Analytics Events)

사용자 행동 데이터를 수집하는 이벤트. 어떤 기능을 얼마나 쓰는지 파악해 제품 의사결정에 활용한다.

**이 서비스에서:** 거래 추가/수정/삭제, 화면 진입 등의 이벤트를 수집한다.

핵심으로 봐야 할 지표:
- **거래 입력 완료율:** 입력 화면 진입 대비 저장까지 완료한 비율 → UX 문제 탐지
- **유형별 거래 분포:** buy / sell / change 비율 → 어떤 행동이 주된 사용 패턴인지
- **재방문 주기:** 환율 변동폭과 DAU의 상관관계

---

## 버전 전략 & 무중단 업데이트

서비스를 중단하지 않고 새 버전을 배포하는 방식. 웹 기반 미니앱은 네이티브 앱보다 업데이트가 훨씬 빠르다.

**이 서비스에서:** Vercel로 배포되어 `git push` 후 수 초 내 전체 사용자에게 새 버전이 반영된다. 앱 스토어 심사 없이 배포할 수 있는 WebView 방식의 최대 장점이다. 단, 토스 자체의 미니앱 심사 프로세스는 별도로 존재한다.
