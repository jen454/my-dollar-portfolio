# 퍼널 진단 및 개선 기록 (2026.07.06)

> 출시(2026.06.21) 후 2주간의 콘솔 지표를 근거로 진단하고, 폼·홈 UX를 개선한 기록.

---

## 1. 문제 인식

- DAU가 출시 직후부터 우하향, 최근 3일은 한 자리수
- 전환 지표(`transaction_save_complete`)는 사실상 개발자 본인뿐

## 2. 콘솔 지표로 그린 퍼널

| 단계 | 이벤트 | 건수 | 전환율 |
|------|--------|------|--------|
| 홈 화면 노출 | `/::screen` | 1,021 | — |
| 기록 화면 진입 | `/add-record::screen` | 51 | 홈 대비 **5%** |
| 저장 완료 | `transaction_save_complete` | 6 | 기록 화면 대비 **12%** (전원 본인 추정) |

참고: 앱 진입(`impression__enter_appsintoss`) 125건, 캘린더(`/transactions::screen`) 38건.

### 진단

1. **유입 문제가 아니라 활성화(activation) 문제.** 구경 트래픽은 있었으나 첫 기록 가치 증명에 실패. 활성화 0 → 리텐션 0 → DAU 자연 감소.
2. **이탈 지점은 두 곳.** 홈→기록 화면 95% 이탈(가치 전달 실패), 기록 화면→저장 88% 이탈(폼 마찰). 특히 후자는 "의도가 있던 사용자 수십 명이 전원 포기"라는 점에서 최우선 병목.
3. **폼 마찰의 구조적 원인**: 입력에 필요한 값(적용 환율)이 미니앱 밖(토스증권 거래내역 상세)에 있음. 확인하러 나가면 재진입 경로가 깊어 복귀하지 않음. `/transactions` 38건은 탐색 의지가 있었다는 방증.

## 3. 반영한 개선

### 기록 폼 (AddRecordPage)

| 문제 | 개선 |
|------|------|
| 적용 환율을 직접 입력해야 함 (사용자가 기억 못 함) | **원화·달러 두 금액 입력 → 환율 자동 역산.** buy: 낸 원화+받은 달러 / sell: 판 달러+받은 원화. 우대율 반영된 실효 환율이 정확히 보존됨 |
| 숫자를 어디서 찾는지 안내 없음 | help 문구: "토스증권 거래내역 > 환전에서 거래를 누르면 …" |
| 확인하러 나갔다 오면 폼이 초기화 | **draft 저장** (localStorage, 24시간 유지, 저장 완료 시 삭제) |
| 저장 버튼이 왜 비활성인지 모름 | 버튼 위에 이유 힌트 표시 |
| 달러 필드에 QWERTY 키보드 | `inputMode="decimal"` |
| 거래 유형 전환 시 입력값 소실 | 값 유지 |
| 역산 환율이 증권사 표시와 소수점 차이 (원 단위 절사 때문, ±0.03원) | 미리보기 아래 "실효 환율" 안내 문구 |
| TDS TextField 타입 에러 | `invalid`/`description` → `hasError`/`help` |

### 홈 대시보드 (HomeDashboardPage, TransactionRow)

| 항목 | 개선 |
|------|------|
| 빈 상태 카피 | "다음 환전부터 1분만 기록해보세요 / 지난 내역은 나중에 채워도 돼요" — 소급 입력 부담 완화 |
| 현재 환율 카드 | 3row → 2row, 라벨 줄에 `현재 환율 · 07.04 기준` 인라인 |
| 내역 행 | 3줄 → 2줄 (`달러 환전 · 06.15` / 환율 t7 semibold 강조), 간격 small → medium |
| 내역 개수 | 4건 → 5건 |
| 잔액 표기 | "잔액" → **"기록 잔액"** (배당금 등으로 실제 계좌와 다를 수 있음을 표기로 예방) |
| 날짜 | 올해는 MM.DD, 연도 다르면 YYYY.MM.DD |

### 계측 (퍼널 완성)

| 이벤트 | 위치 | 목적 |
|--------|------|------|
| `record_cta_click` | RecordCTA | 기록하기 버튼 클릭 의도 측정 |
| `transaction_input_start` | AddRecordPage 첫 입력 시 | "폼 보자마자 이탈 vs 쓰다 포기" 구분. draft 복원 재진입은 중복 집계 제외 |
| `transaction_save_complete` | 기존 | 최종 전환 |

배포 후 퍼널: `홈 → record_cta_click → /add-record::screen → transaction_input_start → transaction_save_complete`

## 4. 성공 기준 (배포 후 확인할 것)

- **기록 화면 → 저장 전환율**: 12% → 유의미한 상승 여부 (핵심)
- `record_cta_click ÷ 홈 노출`: 홈 가치 전달 개선 여부
- `input_start ÷ /add-record 노출`: 폼 첫인상에서의 이탈 여부
- 단, DAU가 한 자리수라 정량 판단에 시간이 걸림 → **지인 3~5명 정성 테스트 병행** 권장
